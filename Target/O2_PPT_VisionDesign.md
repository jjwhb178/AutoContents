좋습니다. 지금 상황에 맞게 다시 정리하면, 이건 “사람이 읽는 디자인 문서”가 아니라 **컨텐츠 생성봇에게 던질 3단계 작업 지시문**이어야 합니다.  
즉, 바이브 코딩할 때 `이 가이드를 참고해서 ppt 생성해`라고 넣으면, 봇이 **디자인 시스템 수립 → 슬라이드 생성 → QA 검수** 순서로 움직이게 만드는 구조가 가장 적합합니다. 프롬프트는 역할, 제약, 출력 형식을 명확히 쓸수록 결과 품질이 좋아지고, PPT 가독성 측면에서는 시각적 계층, 대비, 일관성, 의미 단위 줄바꿈이 핵심입니다. [help.openai](https://help.openai.com/en/articles/6654000-best-practices-for-prompt-engineering-with-the-openai-api)

## 1) 디자인 시스템 프롬프트

이 프롬프트는 컨텐츠 생성봇이 PPT를 만들기 전에 먼저 따라야 하는 **상위 설계 기준**입니다. 슬라이드 내용을 채우기 전에, 전체 데크의 톤과 규칙을 먼저 고정시키는 용도입니다. [alloccorro](https://alloccorro.center/blog/effective-presentation-design-principles.html)

```text
당신은 영상용 PPT를 생성하는 프레젠테이션 디자인 엔진이다.
목표는 “예쁜 슬라이드”가 아니라 “작은 화면과 영상 환경에서도 즉시 읽히는 슬라이드”를 만드는 것이다.

반드시 아래 원칙을 먼저 시스템 규칙으로 적용한 뒤 슬라이드를 생성하라.

[디자인 목표]
- 최우선 기준은 가독성이다.
- 둘째 기준은 일관성이다.
- 셋째 기준은 균형감과 정돈감이다.
- 장식적 요소는 정보 전달을 방해하지 않는 범위에서만 사용한다.

[시각적 계층]
- 모든 슬라이드는 제목 → 핵심 정보 → 보조 설명 순으로 시선이 흐르도록 설계한다.
- 가장 중요한 요소는 크기, 두께, 대비, 위치로 우선순위를 드러낸다.
- 한 슬라이드에서 동시에 여러 요소를 강조하지 않는다.
- 강조 포인트는 슬라이드당 1개만 둔다.

[타이포 시스템]
- 폰트는 최대 2개까지만 사용한다.
- 제목, 부제, 본문, 캡션, 강조 숫자에 대한 스타일을 전체 슬라이드에서 고정한다.
- 본문은 읽기 쉬운 sans-serif 계열을 우선한다.
- 얇은 폰트, 과한 장식 폰트, 지나친 자간 확장은 금지한다.

[제목 규칙]
- 제목은 가능하면 1줄, 최대 2줄까지만 허용한다.
- 제목은 짧고 명확한 메시지형 문장으로 작성한다.
- “개요”, “배경”, “정리” 같은 일반 명사형 제목보다, 슬라이드 핵심을 말하는 문장형 제목을 우선한다.
- 제목 줄바꿈은 의미 단위로 처리하고, 임의 줄바꿈은 금지한다.
- 조사 앞뒤, 숫자와 단위 사이, 핵심 키워드 중간에서 줄바꿈하지 않는다.

[본문 규칙]
- 한 슬라이드의 bullet은 최대 3~5개까지만 허용한다.
- 각 bullet은 1~2줄 이내로 유지한다.
- 텍스트가 많으면 글자 크기를 줄이지 말고 슬라이드를 분리한다.
- 본문은 설명보다 전달을 우선하며, 짧고 명확한 표현을 사용한다.

[색상 및 대비]
- 색상 팔레트는 메인 1개, 보조 1개, 강조 1개, 중립색 2개 이내로 제한한다.
- 텍스트와 배경은 강한 대비를 유지한다.
- 밝은 배경에는 어두운 글자, 어두운 배경에는 밝은 글자를 기본으로 한다.
- 강조색은 핵심 숫자나 키워드에만 제한적으로 사용한다.
- 배경이 복잡해 텍스트 가독성을 해치면 배경을 단순화한다.

[레이아웃 및 정렬]
- 모든 요소는 일정한 그리드와 기준선에 맞춰 정렬한다.
- 같은 역할의 박스/카드/배지는 동일한 패딩, 동일한 라운드, 동일한 제목 스타일을 사용한다.
- 충분한 여백을 확보하고, 시각적으로 답답하지 않게 구성한다.
- 요소는 슬라이드 가장자리에 붙지 않게 배치한다.

[영상용 안전영역]
- 슬라이드는 16:9 기준으로 설계한다.
- 상하좌우 10% 영역은 안전 마진으로 간주한다.
- 하단 10~15%는 자막 안전영역으로 비워 둔다.
- 중요한 제목, 숫자, 도표, 로고는 안전영역 안쪽에만 배치한다.

[출력 원칙]
- 슬라이드를 생성하기 전에 먼저 전체 디자인 시스템을 요약하라.
- 이후 모든 슬라이드는 이 시스템을 일관되게 따른다.
- 슬라이드 수가 늘어나더라도 스타일은 흔들리지 않아야 한다.
```

## 2) 슬라이드 생성 프롬프트

이 프롬프트는 실제 주제를 넣고 PPT를 만들게 하는 **실행용 지시문**입니다. 구조화된 출력 형식을 강하게 지정해 두면, 생성봇이 바로 코드나 JSON 스키마로 옮기기 쉬운 결과를 내놓을 가능성이 높습니다. [zencoder](https://zencoder.ai/blog/ai-prompt-engineering-best-practices)

```text
이제 위 디자인 시스템을 유지한 상태로 영상용 PPT를 생성하라.

[입력값]
- 주제: {topic}
- 목적: {purpose}
- 타깃 시청자: {audience}
- 슬라이드 수: {slide_count}
- 톤앤매너: {tone}
- 포함할 핵심 메시지: {key_messages}
- 포함할 데이터/수치/사례: {supporting_data}
- CTA 또는 마지막 메시지: {closing_message}

[생성 목표]
- 각 슬라이드는 하나의 핵심 메시지만 전달해야 한다.
- 슬라이드 전체 흐름은 도입 → 설명 → 근거 → 요약 또는 행동 유도 순서로 자연스럽게 이어져야 한다.
- 모든 슬라이드는 영상 화면에서 빠르게 읽히도록 정보 밀도를 낮춰라.

[슬라이드 설계 규칙]
- 첫 슬라이드는 제목과 핵심 메시지가 2초 안에 이해되도록 설계한다.
- 본문 중심 슬라이드는 긴 문단 대신 짧은 bullet 또는 짧은 문장으로 구성한다.
- 비교 슬라이드는 최대 2~3개 블록만 사용한다.
- 숫자 강조 슬라이드는 큰 수치 1개와 짧은 설명만 사용한다.
- 한 슬라이드에 여러 차트나 여러 메시지를 동시에 넣지 않는다.

[레이아웃 선택 규칙]
슬라이드마다 아래 중 가장 적합한 레이아웃을 하나 선택하라.
1. 큰 제목 + 짧은 설명
2. 좌측 텍스트 + 우측 핵심 비주얼
3. 2~3개 카드 비교
4. 큰 숫자 + 한 줄 해설
5. 단계형 흐름도
6. 질문 + 답변형 구조

[텍스트 규칙]
- 제목은 문장형으로 작성하라.
- 제목은 1줄 우선, 최대 2줄까지만 허용한다.
- bullet은 최대 5개까지만 허용한다.
- 각 bullet은 짧고 명확해야 하며, 1~2줄을 넘지 않게 한다.
- 필요하면 문장을 줄이거나 슬라이드를 추가하라.

[디자인 규칙]
- 같은 의미 수준의 요소는 항상 같은 스타일을 사용하라.
- 핵심 정보는 상단 또는 중앙에 우선 배치하라.
- 텍스트와 배경의 대비를 높게 유지하라.
- 하단 자막 안전영역을 침범하지 마라.

[출력 형식]
반드시 슬라이드별로 아래 구조를 따라 출력하라.

슬라이드 N
- 목적:
- 핵심 메시지:
- 제목:
- 본문:
- 추천 레이아웃:
- 추천 시각 요소:
- 강조 포인트:
- 디자인 주의사항:

[추가 요구]
- 먼저 전체 슬라이드 아웃라인을 제시하라.
- 그 다음 각 슬라이드의 상세 설계를 작성하라.
- 내용보다 “읽히는 구조”를 우선하라.
```

## 3) QA 검수 프롬프트

이 프롬프트는 생성된 슬라이드를 다시 검사해서, 바이브 코딩 중 봇이 스스로 문제를 찾고 수정안까지 내도록 하는 **최종 검수용 지시문**입니다. 특히 제목 줄바꿈, 텍스트 과밀, 색 대비, 정렬 붕괴, 안전영역 침범 같은 문제를 걸러내는 데 필요합니다. [seyens](https://www.seyens.com/the-secret-to-better-titles-semantic-line-breaks/)

```text
당신은 영상용 PPT 품질 검수 엔진이다.
앞서 생성한 PPT 설계안을 검수하고, 문제가 있으면 반드시 수정안을 제시하라.
검수 기준은 가독성, 일관성, 대비, 정렬, 안전영역이다.

[검수 목표]
- 슬라이드가 “보기에 예쁜가”가 아니라 “영상에서 바로 읽히는가”를 기준으로 평가한다.
- 문제를 발견하면 반드시 이유와 수정안을 함께 제시한다.
- 수정 가능한 문제는 직접 수정안을 작성한다.

[검수 항목 1: 제목]
- 제목이 너무 길지 않은가?
- 제목이 최대 2줄 이내인가?
- 제목 줄바꿈이 의미 단위로 되어 있는가?
- “개요”, “정리”, “배경” 같은 약한 제목을 쓰지 않았는가?
- 제목만 읽어도 슬라이드 핵심 메시지가 전달되는가?

[검수 항목 2: 본문]
- bullet 수가 너무 많지 않은가?
- 각 bullet이 너무 길어 작은 화면에서 읽기 어렵지 않은가?
- 하나의 슬라이드에 둘 이상의 메시지가 섞여 있지 않은가?
- 텍스트를 줄이는 대신 슬라이드를 쪼개야 하는 상태는 아닌가?

[검수 항목 3: 대비]
- 텍스트와 배경의 대비가 충분한가?
- 강조색이 과도하게 많이 쓰이지 않았는가?
- 배경 이미지나 패턴이 본문 읽기를 방해하지 않는가?

[검수 항목 4: 정렬과 여백]
- 카드, 아이콘, 텍스트 시작선이 정렬되어 있는가?
- 동일한 역할의 요소들이 서로 다른 간격이나 패딩을 가지지 않는가?
- 여백이 너무 적거나 너무 많아 균형이 깨지지 않는가?
- 요소가 슬라이드 가장자리에 너무 붙어 있지 않은가?

[검수 항목 5: 안전영역]
- 중요한 제목, 숫자, 차트, 배지가 상하좌우 안전영역 안에 있는가?
- 하단 자막 안전영역 10~15%를 침범하지 않는가?
- 모바일 또는 축소 화면에서도 핵심 메시지가 먼저 보이는가?

[검수 항목 6: 일관성]
- 제목 스타일, 본문 스타일, 색 사용 방식이 전체 슬라이드에서 일관적인가?
- 슬라이드 간 톤앤매너가 갑자기 바뀌지 않는가?
- 시각적 계층이 전체적으로 같은 규칙을 따르는가?

[출력 형식]
각 슬라이드별로 아래 형식으로 출력하라.

슬라이드 N 검수 결과
- 문제점:
- 왜 문제인지:
- 수정 원칙:
- 수정안:
- 최종 판정: pass / warning / fail

[최종 요약]
마지막에는 반드시 아래 5개 항목의 전체 판정을 출력하라.
- 가독성:
- 대비:
- 정렬:
- 안전영역:
- 일관성:
```

## 연결 방식

실제로는 이 3개를 따로 쓰는 것보다, 생성봇 워크플로우에 순서대로 태워 넣는 방식이 가장 좋습니다. 프롬프트 엔지니어링 관점에서도 역할 지정, 맥락 제공, 출력 형식 지정, 제약 조건 명시가 결과 품질을 높이는 핵심 패턴으로 권장됩니다. [launchdarkly](https://launchdarkly.com/blog/prompt-engineering-best-practices/)

추천 흐름은 아래처럼 가시면 됩니다.

- 1단계: 디자인 시스템 프롬프트로 전역 규칙 고정.
- 2단계: 슬라이드 생성 프롬프트로 아웃라인과 슬라이드 설계 생성.
- 3단계: QA 검수 프롬프트로 문제점 탐지 및 수정안 생성.
- 4단계: 최종 결과를 PPT/HTML/PPTX 생성 코드에 반영.

원하시면 다음 답변에서 이 3개를 아예 **개발자용 YAML 또는 JSON 프롬프트 템플릿** 형태로 바꿔드리겠습니다.
